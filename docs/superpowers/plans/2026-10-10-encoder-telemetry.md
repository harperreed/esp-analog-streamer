## Outcome and public contract impacts to acknowledge before implementation

Every logger currently reached by stream.rs::encode must move to bounded numeric records consumed by existing audio-metrics. Playback, encoder/reset/retirement ownership and probe phase/timing policy remain unchanged. No capture-ring/codec redesign, generic queue framework, histogram, priority/stack change, additional task or fallback.

Existing telemetry line prefixes and numeric fields remain; append producer epoch/window/time metadata. UART prefix/host arrival now means export time, not encoder observation time. Numeric terminal io error reporting preserves failure truth but may change human-readable error detail. Probe invalidation no longer dumps private Debug state; retain its consumed numeric fields and invalidation reason. These are explicit observable diagnostic changes, not a claim of byte-identical logs.

The current acquisition harness will require the new epoch/window/baseline/capture-bound metadata for any successful acceptance. Old synchronous logs become insufficient evidence for new acceptance. Do not add a legacy/async switch, version shim, fallback chronology, or parallel supported acceptance path. Preserve original archived UART, provenance and saved result bytes; do not rewrite history to pass the new harness. Update synthetic positive fixtures to current metadata. The archived real raw-loss regression MUST still reject for its actual raw overrun/reset/invalidation evidence, even though it also lacks new metadata. Its test must assert that real loss reason explicitly; rejection solely for missing metadata would weaken the regression. Historical offline receipts remain historical artifacts, not newly certified results.

## Record and queue contract

Dedicated capacity TWO fixed array queue behind Mutex with try_lock-only publish/take. Use AtomicU32 wrapping cumulative dropped and full/contended/poison reason counters plus an independent sticky AtomicBool loss flag, matching the now-existing listener reason semantics. Reason sums need not equal total during concurrent sampling. No allocation, String, live io::Error, formatting, blocking lock, retry loop, socket/ring/codec/Arc ownership or callbacks retained in records. Dequeue one local record and release storage before logging. Drain at most two records per metrics iteration independently of the listener budget.

Window: start/end producer timestamps, telemetry epoch identity and window identity; actual snapshot of all existing EncoderMetrics fields plus feature-only actual Probe::Report. Publish stream-encode and its probe partner as ONE queue record; exporter emits the pair in order with matching identity. Runtime/stack samples must come from encoder owner, never exporter. Cumulative frames/resets remain cumulative exactly as today; window fields reset exactly once even on publication loss.

Boundary: one combined fixed record for same-turn reset/invalidation/replacement storage/format announcement. Snapshot existing position and consumed invalidation counters; fixed reasons describe overrun/switched/stopped. Storage copies numeric receipt values before they expire and includes fresh baseline timestamp. Preserve logical invalidation then storage then baseline then active-format relation through metadata, regardless of export time. Assert output capacity on owner as today. Startup publishes one storage/baseline boundary. Failure contains numeric ErrorCode and producer identity/time; a stopped turn may publish boundary then Failure, maximum two records.

Runtime Epoch has no numeric id; do not invent an API or use an address as durable identity. Add ONE telemetry-only owner epoch counter advanced on Switched; reset remains same runtime epoch with the actual incremented probe sequence. Use checked increments and sticky telemetry-invalid/loss if exhausted, rather than silently wrap identities. Window IDs may be a single owner counter; Probe::Report sequence/phase/interval remain authoritative probe identity, not another phase tracker. Keep boot/reset acquisition separation from existing collector reset provenance; a telemetry epoch is not a global boot identifier.

Capacity two covers startup, normal report or combined lifecycle boundary and the terminal two-record turn. It does not guarantee loss-free arbitrary fault storms or a blocked consumer. Full storage must drop honestly and encoding must continue. No evidence justifies capacity four yet.

## Capture coverage and strict acceptance

Inside existing out-of-line log_capture: sample begin with the same esp_timer_get_time/micros clock, call i2s_capture::counters, eagerly load FRAMES and every coverage fault counter (DROPPED, READ_ERRORS, RESTARTS, SUPERVISOR_RESTARTS, OVERFLOW_RESTARTS, SETTLING_DISCARDED_FRAMES, GAPS, HEALTH_RESTART_REQUESTS), sample end immediately, then proceed to heap/runtime/formatting. Log these saved values. No participating load may stay in logger arguments after end. Do not include the separate observed timing-deficit accumulator, heap work, timing-max swaps or formatter in the capture bound.

These are separate Relaxed atomic loads, not a coherent snapshot. Bounds limit observation time; no new writer synchronization or ISR/capture work is authorized. Compare per-counter monotonicity and fault stability; preserve wrap/missing-interrupt limits. Capture coverage requires preceding snapshot end <= encoder window start and following snapshot begin >= window end, with every intervening capture report inspected. Overlap/missing/reversed bounds yields unknown/rejection, never zero loss.

Parser pairs encoder/probe by exact epoch/window/start/end and sequence identity, not adjacent UART order. Storage ties to its exact producer baseline and sequence. Reconstruct per-owner event ordering with explicit identities; preserve original arrival provenance. Reject missing/duplicate/malformed fields, contradictory pairs, discontinuous window IDs, sequence/phase jumps, missing required lifecycle/final evidence and any relevant sticky export loss, including total drop count wrapping to zero. Delay does not erase raw overruns, resets or invalidation. Preserve the conservative rejection of deferred listener activity in probe acquisition; correlating that activity is outside this unit.
