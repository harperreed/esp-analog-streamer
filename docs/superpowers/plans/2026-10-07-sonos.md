# Sonos Implementation Plan

> For agentic workers: use subagent-driven-development, task-by-task, with independent review. Work on the current WIP branch; no worktree or push is needed.

**Goal:** Standalone web-configured Sonos playback of the board's analog stream, followed by opt-in audio-triggered playback.
**Architecture:** Pure bounded protocol/policy logic in core, one firmware control worker, short HTTP handlers, one existing FLAC encoder/server.
**Tech stack:** Rust, pinned ESP-IDF5.5.5/esp-idf-svc0.53.0, managed WebSocket client, existing serde_json, NVS.
**Spec:** `docs/superpowers/specs/2026-10-07-sonos-design.md`, approved by Doctor Biz in chat.

## Global constraints

- Real target: Altec + 3, explicitly authorized; group test volume at most5%, never raise a lower setting.
- Verify Sonos trust chain; approved hostname-check exception applies only to this connection.
- No dependency on workstation in the final product. No automatic codec fallback.
- No capture/encoder network waits. Bound discovery, JSON messages, queue depth and all deadlines.
- No credential values in tracked files. Preserve other controllers' session ownership.
- Unit/integration tests and real board/Sonos/browser validation; canonical check is `scripts/check`.

## Review focus

- Speaker regrouping changes runtime group IDs: resolve stable player identity before starting.
- Another app evicts our session: Stop/reconnect must not pause or steal the new session.
- Fragmented/oversized messages and stale replies: bounded assembler and exact command correlation.
- Noise, opposite-phase stereo and boot during music: energy detection and explicit quiet-before-rearm policy.
- TLS allocation pressure while streaming: measure internal heap/largest block and task stacks on hardware.

## Task 2: Core protocol and autoplay policy (worker)

Files: `core/src/sonos.rs`, `core/src/lib.rs`; tests alongside module.

Interfaces:
- `DiscoveryGroup { player_id: String, group_id: String, household_id: String,
  name: String, host: Ipv4Addr }` with Serialize/Deserialize as needed.
- `parse_discovery(packet: &[u8], peer: Ipv4Addr) -> Result<Option<DiscoveryGroup>, Error>`.
  Leaders only; reject malformed/oversized packets and mismatched WSS host/port/path.
- `SonosConfig { player_id: Option<String>, autoplay: bool }`, default no selection/off.
- Command/reply serialization helpers with explicit8KiB message bound and cmdId matching;
  errors must not treat unsolicited events as command success.
- `Autoplay` policy takes monotonic milliseconds, finite dBFS, enabled/ownership events;
  yields Start/Stop/None.500ms active,10s quiet; startup/stop/eviction require quiet then new audio.

- [ ] Write and run failing tests for discovery bounds, leader/follower selection, scope IDs,
  malformed JSON, stale replies, timing boundaries, nonfinite level, cancellation/rearm.
- [ ] Implement minimal pure logic; keep ownership side effects out of the module.
- [ ] Run module tests, fmt and clippy; independent review before integration.

## Task 3: Firmware controller (worker after core interface review and format proof)

Files: `firmware/src/sonos.rs`, managed-component/Cargo configuration, public CA asset/provenance.
Parent owns main/web wiring to avoid overlap.

Interfaces:
- `start(...) -> SonosHandle`: one worker, bounded command channel, shared status snapshot.
- Commands Discover, Select(stable player ID), Play, Stop, SetAutoplay(bool).
- Read-only snapshot for UI with groups, selected identity, autoplay, state and last error.
- Worker receives current board address and audio level without holding locks across I/O.

- [ ] Measure allocation sizes; callbacks only enqueue bounded data and never block capture.
- [ ] Independent review of unsafe boundaries, cleanup and session ownership.

## Decisions and progress

- Architectural design approved; user prefers delegated implementation. Execute this plan
  without asking for another general permission to implement the same approved scope.
- Codec acceptance is a real hardware gate, not a reason to substitute MP3 silently.

- Live local WSS control is verified with CA validation; Altec + 3 is capped at5%.
  Native board FLAC and a byte-preserving host relay briefly play then rebuffer.
  Host-generated native24-bit FLAC also rebuffered, so the ESP32 is not required
  for this symptom. Ogg URL extension was rejected before fetching; Ogg-FLAC
  under a .flac filename was fetched but also rebuffered.16-bit control ongoing.
- Ruling: fix per-listener native FLAC numbering independently of Sonos cause.
  RFC9639 requires numbering from the beginning of a stream; our fresh header
  precedes nonzero shared frame numbers. Rebase copied headers/CRCs without
  duplicating encoders. Host decoders tolerated this, but no root-cause claim
  follows. Add focused independent-decoder tests before hardware comparison.
- Sonos phase compaction count0. Parent owns all live audio/device mutations;
  workers own disjoint core protocol, audio meter and FLAC numbering files.
