## Scope and activation

The current firmware, core and MP3 manifests contain no `encoder-probe` feature, and there is no existing runtime encoder-probe activation interface. The existing `capture-fixture` is a host atomic-copy fault boundary, not an encoder timing toggle. All feature names and receipt APIs below are proposals.

Keep the earlier proposed default-off `encoder-probe` feature, forwarded by firmware and core to `esp-shazam-mp3/encoder-probe`; core needs it because integration tests include firmware modules by path. Preserve normal features and C flags. Gate the live-allocation C query, receipt methods, probe state and extra timing work. Translate Cargo's feature into a private C define in `mp3/build.rs`.

Use task-local automatic OFF → ON → OFF phases within one ELF. Emit a one-time storage receipt before constructing the measurement baseline; at the start of each OFF/ON/OFF phase discard two complete ten-second report intervals, then retain six complete intervals (24 total report intervals). The first interval after a transition includes the preceding report and transition work because the existing snapshot precedes logging; per-phase settling bounds this carryover without changing snapshot semantics. Two windows are a defined discard policy, not proof that drift has ended. Label all reports with sequence, phase, interval and validity. After completion remain OFF. Phase changes happen after reporting the completed interval and clearing probe totals. There is no HTTP endpoint, shared toggle, allocator collector or per-frame log. Any `EncoderStep::Switched` invalidates the current sequence and storage receipts, including same-format MP3 worker replacement, because commit replaces the codec and output Vec. Start a new sequence only when the resulting format is MP3. Mark raw Overrun invalid immediately from `RawAttempt`; successful `Reset` is not required to preserve this failure. Reset failure returns `Stopped` before emitting `Reset`: retain both the failed attempt and stopped/error receipt, with no restart. After successful reset or switch, preserve the invalid sequence and lifetime frame/reset evidence (or emit explicit old/new cumulative baselines), take fresh full storage receipts, then establish a fresh wall/runtime baseline and clear interval totals before starting OFF1 settling. Never divide pre-reset RawWait by a post-reset elapsed denominator; no failed window disappears merely because a fresh sequence starts.

Preserve codec, input conversion, priorities, output reservation, raw/encoded capacities, cursor/reset rules, existing observations, production metric updates, eight-frame MP3 delay and full `CAUGHT_UP_SLEEP` behavior in every phase. This bounds incremental enabled-probe cost; OFF still contains feature-built layout, branches and existing instrumentation.

## Actual measurement sites

1. `stream_pipeline.rs::EncoderPump::step_read` already measures exactly the `read(...)` call and emits `EncoderObservation::RawAttempt { result, elapsed }`. Consume that duration in the existing `stream.rs::encode` observation closure, summing successful `Ok(n > 0)` separately from `Ok(0)`/Retry/Overrun. No new read clocks or replacement helper are needed. Preserve `RAW_READ_MAX_US` and existing counts in OFF and ON. Probe OFF skips only the new sums. Existing `RawAttempt` clocks still run in OFF; never claim they are disabled.
2. The shared pump emits `RawWait(Duration)` after the read wait reaches Ready, Stalled or Failed. This existing wall interval spans attempts, observation processing, retry sleeps and scheduling. Preserve it. Successful/rejected attempt sums are nested in this interval; report `raw_wait - success_attempt - rejected_attempt` as a checked remainder, not idle time. Current reports occur only when Publication, Reset, Stalled or CursorWaitExpired sets `log_due`; Spin/SleepUntil turns never report. Thus no pending raw wait crosses a report boundary; preserve that property and never add a timer-driven report to every loop.
3. `AcceptedInput` currently fires immediately before `worker.encoder.push(&self.chunk[..2 * n])`. It contains positions and frames, not elapsed conversion time. Add a feature-gated PCM-push duration observation around exactly that push, using the pump's existing injected `now` closure only when the step's snapshotted probe gate is ON. Do not move AcceptedInput or infer conversion time from it. A small feature-gated pump configuration/setter is sufficient; avoid changing normal-build pump signatures or creating a second pump. Forward the added observation through the production closure; inspect exhaustive matches in replay support/tests.
4. Existing `Codec(Duration)` wraps `encode_block`, which includes output resize and the bridge's frame copy/validation, as well as Shine. Preserve its exact scope; call it codec-call wall, not exclusive Shine CPU time. Existing `Publication { lock_wait, held }` measures encoded-ring lock wait and push. Its held duration ends before `drop(output)`, so lock-release overhead remains in the residual.
5. `stream.rs::encode` owns actual `vTaskDelay(1)` after eight published MP3 blocks. Time exactly that unchanged call when ON, counting calls and wall duration; no assumed tick charge. Only under compile-time `encoder-probe`, move the existing `if log_due { metrics.log_if_due(...) }` check immediately after this delay block. Normal firmware without the feature retains its existing report-before-delay order. Runtime OFF and ON within the diagnostic ELF both use report-after-delay order; the eighth-publication counter and delay stay unchanged. Snapshot the gate for the pump operation and its resulting wrapper delay. The pump publication completes before the wrapper delay and report; this avoids assigning a block's delay to the next phase. Preserve reset/stall checks. Make the reporting method expose whether it actually emitted an interval so the phase advances only on real reports, not every `log_due` check.

For the disjoint accounted wall total use existing outer raw wait + new PCM push + existing codec + existing publication wait/held + new actual delay. Use checked subtraction from interval elapsed and flag invalid arithmetic; do not mask negative residuals with saturation. Timer pairs and observation callbacks outside measured spans, cursor acquisition/service/reset work, loop/report overhead and preemption contribute to the residual. All spans include preemption; runtime charge includes charged interrupts and excludes the unfinished scheduling slice. These figures cannot prove cache misses or exclusive CPU attribution. Report work belongs to the next interval under existing `since_us` semantics.

The existing raw-attempt duration is available in OFF with no added clocks, but keep the new aggregation gated for a clean incremental-cost comparison. ON-only push/delay totals cannot be reconstructed for OFF. Encoded frames and resets remain lifetime counters within an epoch; use consecutive deltas. Existing wall totals and raw counters reset on each report.

## Storage receipts

The pump now owns the private chunk Vec. Add only a feature-gated read-only method returning backing pointer, initialized byte length and allocated byte capacity. Take this receipt after `EncoderPump::new`, together with raw `payload_range()`/`stamps_range()`, worker output Vec and adapter PCM backing storage. Do not expose Vec handles, add inspection locks or make fields public. `Prepared::new` reserves `format.max_frame_bytes()`; MP3's fixed output is 960 bytes. Prove capacity covers resize and record actual capacity without pre-encoding or added allocation.

Keep the earlier direct C query. Pinned `layer3.c` allocates configuration using `sizeof(shine_global_config)` and bitstream using `BUFFER_SIZE`; `bitstream.h` defines 4096. `config->bs.data` and positive `bs.data_size` identify the live second allocation. Return pointer/size pairs through a matched C/Rust receipt, guarding signed conversion. The owning Rust encoder and adapter forward copies without exposing an owning handle or a new Send/Sync contract. Querying never allocates, frees or mutates. Existing target allocation requests are `heap_caps_calloc(1, size, MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT)` and frees use `heap_caps_free`; host uses malloc/free. No new ESP memory-classification API is needed. Addresses do not prove cache behavior. Invalidate receipts on replacement/reset; retain failures rather than silently discarding them as settling.
