# Kata 89g8: deterministic production replay design

Doctor Biz, this is a proposed architecture for review, not an implementation or
an acceptance result. Reviewed Kata 89g8 and closed prerequisite 4dss against
current core and firmware source. No builds, hardware actions or source edits.

Implementation checkpoint: the bounded shared writer slice below now passes
independent review, seven deterministic replay tests, 31 real writer tests and
all 22 canonical stages. The broader architecture remains proposed; this slice
does not close 89g8. The design's original read-only scope is distinct from this
later implementation and its verification.

## Finding and scope

CaptureBuffer/StreamRing, FLAC Encoder and FlacRing already run on the host.
CaptureBuffer::invalidate and the capture-fixture read_with_copy_hook expose
real generation loss, including invalidation during an atomic copy. Slot also
runs on the host. These should remain the only PCM, codec, ring and slot engines.

The missing seam is production orchestration. firmware/src/stream.rs owns
encode and stream_compressed; stream_wait hardcodes Instant/sleep, buffered
admission checks TcpStream, and DeadlineWriter hardcodes send/poll/Instant.
Calling the rings from a separately written test loop would not replay actual
production reset, admission, timeout, numbering or cleanup decisions.

Start with FLAC data-plane replay and explicit listener cancellation. Do not
claim to replay Sonos ownership or final create/load cancellation: those control
operations require their own shared seam and pqqq policy. MP3 correctness remains
outside this sample-exact FLAC workload; leave its adapter and target behavior
intact when moving shared orchestration.

## Incremental delivery and review boundary

First implement only the shared resumable byte-offset/deadline write transition
and its production adapter, plus a test pipeline that publishes real PCM into
CaptureBuffer, invokes the actual FLAC encoder and FlacRing, renumbers real
frames and sends them through that shared operation into bounded artifacts.
Inject only environment outcomes: virtual time, send capacity and readiness.
Assertions must decode actual generated bytes and compare source samples; a
script that merely checks its own scripted return values is not a useful test.
No production mock mode. This first slice can cover short-write/cancel tails
and exact codec/ring delivery, but it remains incomplete for production encoder
reset/admission/churn orchestration. Explicitly leave Kata 89g8 open.

Review the wider extraction below before proceeding. Migrate one existing
production decision at a time into the shared module, with characterization
regressions; do not build the whole engine first. Estimated first slice is
100–180 changed production lines and 200–350 test/validator lines. Parent may
choose it as a bounded implementation after seam review without approving the
full extraction.

## Proposed bounded extraction

Move the existing encoder block assembly/reset decisions and compressed listener
admission/read/renumber/write-completion decisions into a small host-buildable
core module. Firmware must call those same steps. Preserve existing contracts,
constants and errors; wrappers retain metrics, logging, RTOS priority/yields,
codec switching and actual resources. Do not introduce a parallel old/new path.

Use explicit monotonic Duration values supplied by callers, absolute deadlines,
and resumable steps returning progress, pending-until, or terminal reason. This
allows one deterministic scheduler to interleave capture, encode and listener
work without threads or recursive callbacks. Keep encoder implementation behind
a minimal adapter using existing frames_wanted/push/encode_block/reset; production
uses its existing selected codec adapter and replay uses the actual core FLAC
encoder. Preserve frames_wanted/block-number/reset behavior exactly.

Extract DeadlineWriter's byte-offset/deadline/error decision loop into a shared
resumable write operation. Production send/poll adapters supply actual results
and elapsed time; replay supplies scripted short sends, Interrupted, WouldBlock,
readiness, hangup and errors. Keep socket flags, errno capture and diagnostics
around actual syscalls in the real adapter. The write operation must never own
a second frame copy, extend the frame's deadline after partial progress, or
advance FLAC numbering before full completion. Poll readiness does not imply a
successful send. A send can finish after its deadline; preserve current behavior
in characterization tests rather than silently strengthen it in this refactor.

Reuse a shared wait-budget decision for raw reads, encoded reads and buffered
admission so scripted time exercises the same deadline/freshness comparisons.
Retain independent admission fill and freshness budgets across generation resets.
Keep lock acquisition and peer-connected observations in adapters. Cooperative
replay can schedule contention outcomes but cannot prove real lock scheduling.

Use actual Slot guards; extract only the connection ownership/release decision
if needed to share close ordering. Simulated close completion must precede slot
release. Production failed-close restart is a distinct terminal event with the
slot still held, not a successful reclamation or an actual host restart.

## Workload and artifacts

A test-only driver owns an integer-microsecond clock and a bounded event queue,
ordered by (time, insertion sequence). Same workload/seed yields identical events
and output. A recorded explicit event schedule is the authoritative regression;
seeds also record the pinned generator/version. Advance to the next scheduled
input or returned deadline; never sleep, read a socket or consult wall time.

Events publish deterministic stereo PCM through CaptureBuffer, pause publication,
invalidate generations, admit/cancel/reconnect listeners, retire an epoch, and
schedule writer results. Inputs identify source sample ranges and generation.
The driver records ordered time/actor/event/result/range decisions. It must not
implement producer/listener recovery policy itself. Keep finite event, virtual
time and emitted-byte limits; stream output and event logs to artifacts and
track configured ring/frame buffers rather than retaining a soak in a Vec.

For capture invalidation during a copy, use the existing capture-fixture hook.
For reset halfway through codec assembly, invalidate after a partial push and
let the shared production raw-read/reset decision run. These test different
boundaries and both matter.

Decode artifacts with actual FFmpeg and reuse scripts/decoder_integrity.py's
FrameHash and decoder-line validation from 4dss through a small host artifact
validator. Use explicit pcm_s32le, exact stereo frame counts, separate FLAC
number/CRC validation, and normalized sample hashes against the known input.
Claxon gives a fast Rust sample-exact cross-check; it does not replace the shared
oracle. Quantize expected FLAC16 samples using the existing clamp/shift contract.
Do not compare hashes with different decoder packet boundaries.

A terminal partial frame is accounted as accepted transport bytes plus an
incomplete tail, never counted as delivered PCM. Decode only a verified complete
prefix when reporting exact samples, and independently assert the tail and
terminal outcome. Each reconnect starts a distinct stream and numbering origin.
Report accepted capture, delivered/decoded, discarded staged/partial PCM, and
known discontinuities separately; no aggregate timeline-duration success.

## Acceptance and TDD sequence

1. Characterize current production decisions before extraction: absent capture
   preserves the encoder's partial block while listeners time out; raw overrun
   discards partial assembly and resets encoded generation; old cursors fail.
   Compare shared steps after migration to these exact outcomes.
2. Successful steady capture with two listeners decodes to exact expected PCM,
   order and channels, including listener-local FLAC numbering at joins.
3. Three-second listener pause runs with production profile capacity and deadline;
   also use small capacity to force overrun. Assert the actual applicable outcome,
   independent peer progress, final slot count, and bounded storage. A three-second
   pause is not automatically a failure or an automatic recovery.
4. Absent capture and buffered admission reset/contended snapshots reach their
   original absolute deadlines. Silent PCM still counts as progress. Retry scratch
   never reaches the encoder.
5. Invalidate mid-copy and mid-assembly: no mixed-generation block, explicit
   discontinuity, old listener termination, and sample-exact fresh reconnect.
6. Short sends plus WouldBlock/Interrupted preserve bytes exactly; timeout after
   a partial frame never advances completed-frame accounting. Include repeated
   writable-then-WouldBlock and poll hangup/error cases.
7. Churn with cancellation before admission, after slot claim, during header and
   partial payload reclaims slots only after close; a stale listener cancellation
   cannot close its replacement. Retirement ends the old epoch. Sonos operation
   cancellation races stay explicitly outside this gate until their seam exists.
8. Run each workload twice and compare byte artifacts and ordered event logs.
   Shrink failing schedules by removing events then reducing durations/chunk sizes,
   preserving the same failure predicate and event dependencies. Persist minimized
   fixture JSON with schema version, seed, expected terminal reason and hashes.
9. Add a finite deterministic replay stage to scripts/check using existing pinned
   host dependencies. Parent runs canonical checks and target compilation after
   hardware measurement releases the machine. Keep socket integration, Loom and
   HIL checks: no host replay proves lwIP mailbox, DMA, FreeRTOS or radio behavior.

## Dependencies and recommendation

4dss is closed; reuse its oracle rather than inventing a second accounting format.
The first replay records today's fail-closed policy. It does not establish
self-healing, bounded media age, capture service recovery or Sonos ownership.
dctv/6vct/pqqq must define any future policies; then implement them in the shared
production decisions and update explicit expected outcomes. Do not block useful
current-policy regressions on choosing those future policies.

Medium risk: extracting orchestration can subtly change timeout edges and
partial-write accounting. Require review of the concrete seam and preserve
behavior before adding new recovery. High limitation: deterministic scheduling
cannot explain the observed device delivery stalls without supporting evidence.
Recommend this narrow extraction before calling any orchestrated replay complete.
A rings-only prototype can prove codec fidelity but cannot close Kata 89g8.

Estimated footprint: 450–700 changed production lines (mostly moves/adapters),
450–700 host driver/tests/fixtures/validator lines, 10–25 check wiring lines.
This is a bounded architectural change requiring parent/Doctor Biz review before
implementation. A materially smaller no-extraction test cannot satisfy the
production-decision requirement honestly.
